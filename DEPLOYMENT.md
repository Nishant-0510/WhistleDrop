# Production deployment

WhistleDrop deploys as two connected services:

- **Frontend:** Vercel (`frontend` root directory)
- **API and database:** Render via the root `render.yaml` Blueprint

## 1. Deploy the API on Render

1. In Render, choose **New > Blueprint** and select this GitHub repository.
2. Render detects `render.yaml` and creates `whistledrop-api` and `whistledrop-db`.
3. Provide secure values for `MODERATOR_USERNAME` and `MODERATOR_PASSWORD` when prompted.
4. Once the API is live, copy its public URL, for example `https://whistledrop-api.onrender.com`.
5. In the API service environment, set `CORS_ALLOWED_ORIGINS` to your Vercel site URL, for example `https://whistledrop.vercel.app`, then save and redeploy.

`JWT_SECRET` is generated by Render. The database connection is injected automatically and is converted to Spring's JDBC configuration at startup.

## 2. Connect Vercel to the API

In Vercel, open **Project Settings > Environment Variables** and add:

```
VITE_API_BASE_URL=https://whistledrop-api.onrender.com/api
```

Use the actual Render API URL. Redeploy the Vercel project after saving the variable.

## Vercel build settings

- Root Directory: `frontend`
- Build Command: `npm run build`
- Output Directory: `dist`

The local developer experience is unchanged: without `VITE_API_BASE_URL`, the Vite development server proxies `/api` to `http://localhost:8080`.
